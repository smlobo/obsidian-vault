### A focused 10-week plan

1. **Weeks 1–2: Learn the ML computation layer.** Work through PyTorch tensors, broadcasting, matmul, reductions, attention, shapes, and dtypes. Inspect a small model with `torch.compile`; trace where graph breaks and recompilations occur. Use the [PyTorch programming model](https://docs.pytorch.org/docs/main/user_guide/torch_compiler/compile/programming_model.html) and [StableHLO specification](https://openxla.org/stablehlo/spec).
    
2. **Weeks 3–5: Build with MLIR.** Complete the [MLIR Toy tutorial](https://mlir.llvm.org/docs/Tutorials/Toy/), then add one tensor optimization of your own—such as a rewrite or lowering for matmul followed by activation. Document the input IR, transformed IR, correctness checks, and measured effect. Study the [Linalg dialect](https://mlir.llvm.org/docs/Dialects/Linalg/) for tiling and fusion.
    
3. **Weeks 6–8: Make a portfolio project relevant to a job.** I’d choose **a small MLIR pass for an inference pattern**, with dynamic-shape and dtype tests, benchmarks, and a short design note. That gives hiring teams concrete evidence for the gap your resume currently leaves open.
    
4. **Weeks 9–10: Add accelerator depth.** If you have GPU access, implement and profile matmul or fused softmax using the [Triton tutorials](https://triton-lang.org/main/getting-started/tutorials/). Explain memory traffic, tiling, and bottlenecks. If you lack GPU access, spend this time on a second MLIR contribution instead.
    

**How I’d position you:** “Principal compiler engineer moving into ML workloads,” with emphasis on IR translation, optimization, code generation, and performance analysis. Keep your AI based Codex plugin as a separate accomplishment; it does not by itself demonstrate AI compiler experience. Your highest value next step is a public, measured MLIR project or upstream contribution—not another general compiler course.
